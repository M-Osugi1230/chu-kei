# 計測の定例化（measurement routine v1）

流入（要件4）と需要（要件3）を、運用負荷を増やさずに観測し続けるための定例です。数値は定義した取得元からのみ取り、取れないものは「未確認」と記録して推測で埋めません。

## 週次（毎週月曜）— 機械的に取れる数値

取得元は本番サイトと repo の公開データのみで、手作業なしに確認できます。

| 指標 | 取得元 | 見る理由 |
| --- | --- | --- |
| 登録済み企業数（current＋expired） | 本番 `data/frontend/company-index.json.gz` の planStatus 集計 | データ資産の増減 |
| サイトマップURL数 | 本番 `sitemap.xml` の `<loc>` 数 | 公開ページの増減 |
| 変更履歴イベント数 | `operations/history/plan-events-v1.json` | 履歴資産の蓄積 |
| 検知inboxの状態別件数 | `operations/detection/inbox-v1.json` | 未処理（open）の滞留検出 |
| 検知ワークフローの成否 | GitHub Actions（detection-watch-*） | 検知の停止検出 |
| サイト稼働 | UptimeRobot（5分間隔・異常時はメール通知） | 障害の即時検知 |

週次の結果はこのチャット（Chu-kei プロジェクト）へ月曜 09:30 目安に届き、`log-v1.md` に1行追記します。過去行は書き換えません。

## 月次（毎月1日、週次と合わせて）— コンソールで確認する数値

ログインが必要なため、確認できた範囲だけを記録します。サインイン等で確認できない場合は「未確認」と記録します。

| 指標 | 取得元 | 見る理由 |
| --- | --- | --- |
| インデックス済み／未登録ページ数と理由 | Google Search Console「ページ」 | 流入の前提条件 |
| 表示回数・クリック数・平均順位 | Search Console「検索パフォーマンス」 | 検索流入の実績 |
| 訪問者数・PV・流入元・上位ページ | Cloudflare Web Analytics | サイト全体の流入 |
| 先行登録（waitlist）件数・問い合わせ件数 | Web3Forms 通知メール（オーナーメールで集計） | 需要の実測 |
| 料金ページの閲覧状況 | Cloudflare Web Analytics／Clarity | 需要検証の補助 |

## 合否基準（週次・月次の報告で各指標に明記する）

2026-11-23にオーナー指示で追加。報告では各指標について合否を明記し、判定に使える数値が取れない場合は「未確認」として合否を付けない。

週次:

- 登録済み企業数: 前週から減っていないこと（減少は不合格＝データ事故として扱う）。
- サイトマップURL数: 前週から減っていないこと。
- 変更履歴イベント数: 前回から減っていないこと。
- 検知inbox: open が2週続けて残っていないこと。
- 検知ワークフロー: 直近の定期実行（TDnet 日次・ソース監視 週次）が成功していること。
- サイト稼働: UptimeRobot のダウン通知がないこと。

月次:

- インデックス済みページ数: 前回確認時から減っていないこと。エラー区分が新たに出ていないこと。
- 表示回数・クリック数: 合否は付けず推移のみ記録する（初期段階のため）。

エスカレーション（合否とは別に、達したらオーナーへ上げる条件）:

- waitlist 登録が累計10件 → アラート実装の判断材料としてオーナーに上げる。

## アクション基準（数値が動いたら何をするか）

- **検知inboxの open が2週続けて残る** → トリアージをまとめて実施する。
- **インデックス済みが減る、またはエラー区分が出る** → 原因を切り分けて先に対応する（流入施策より優先）。
- **waitlist 登録が累計10件** → アラート実装の判断材料としてオーナーに上げる。
- **UptimeRobot のダウン通知** → 定例を待たず即時に対応する。
- **登録済み企業数・イベント数が減る** → データ事故の可能性があるため即時に確認する（通常は増えるか不変）。

## 運用メモ

- 週次計測は「見るだけ」の定例です。数値を見て自動でサイトやデータを変更することはしません。対応が必要なものは通常の PR フローで扱います。
- Search Console の「ページ」レポートは反映に数日かかるため、取得値には必ずデータ日付を併記します。
- 計測の実行経路に恒常的な人手は置きません。週次はスケジュール実行、月次は週次の初回に合わせて確認します。
