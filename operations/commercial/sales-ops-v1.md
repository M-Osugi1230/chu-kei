# 受注フローと販売実務（sales-ops v1・下書き）

スポット調査の受注から入金までの流れと、販売に必要な実務の整備状況です。価格の正本は `offers-v1.json`。この文書は下書きであり、★印はオーナーの決定・確認が必要な箇所です。

## 受注フロー

1. **問い合わせ受付**：サイトのフォーム（general-inquiry / spot-report-request）。Web3Forms 経由でメール通知。
2. **ヒアリング**：対象企業・比較軸・用途・希望納期を確認（`intake.example.json` の項目に沿う）。投資助言に当たる依頼（銘柄推奨・売買判断）は受けない。
3. **見積**：`estimate-template-v1.md` で作成。金額は offers-v1.json の pilot 価格を起点に、対象社数と範囲で確定。納期・修正回数（1回まで含む）・支払条件を明記。
4. **発注確定**：見積への同意をもって作業開始。原則として着手前入金（初回取引）／納品後請求（継続取引）は ★要決定。
5. **納品**：レポートを納品し、出典と確認日を付す。修正1回まで対応（offers の commonTerms）。
6. **請求・入金**：`invoice-template-v1.md` で請求。入金確認をもって完了。

## 決済手段（★要決定）

| 候補 | 手数料の目安 | 備考 |
| --- | --- | --- |
| 銀行振込 | 振込手数料は先方負担が慣行 | 手続きは最も軽い。請求書ベースの B2B と相性が良い |
| Stripe | 決済額の 3.6% 前後 | カード・リンク決済。将来のサブスク（アラート）にもそのまま使える。アカウント開設と本人確認が必要 |

当面のスポット調査は銀行振込だけでも成立します。アラートの月額課金を始める時点で Stripe が必要になるため、その時点で開設するのが効率的です。

## 特定商取引法に基づく表記（★要確認）

- 有料サービスをオンラインで販売する以上、表記ページ（サイトに `legal.html` 等）を用意します。下書きは `tokushoho-draft-v1.md`。
- 個人事業の場合、氏名・住所・電話番号の扱いが論点です。「請求があった場合に遅滞なく開示する」方式が一般的に使われますが、表示名（屋号の有無）を含め ★オーナーの確認が前提です。公開前に専門家の確認を推奨します。
- 現時点では有料販売の実績がなく、スポット調査は見積ベースの個別契約のため、表記は「販売開始までに整備」で足ります。ただし先行登録やレポート販売（不特定多数向けの販売）を始める前に必須です。

## その他の実務

- **領収書**：請求書と支払い記録で代替できる旨を案内。求められた場合は発行する。
- **消費税**：offers の価格は税別表示。請求時に税額を明記する（インボイス制度への対応＝適格請求書の発行可否は ★要確認：登録事業者でない場合はその旨を先方に伝える運用にする）。
- **記録**：受注・納品・請求の記録は repo の operations 配下ではなく、オーナーの管理下に置く（顧客情報を GitHub に置かない）。
