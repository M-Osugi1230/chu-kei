## 2. Phase 0 Quality Rebase

2026-08-01に旧5つ星評価を廃止し、3,000社を再分類した。

- 315社: 非テンプレート型で再監査対象
- 2,685社: テンプレート型・深掘り前
- 610社: 資料名が決算短信等で、正式な中期経営計画を厳格に再探索する対象
- 353件 / 100社: 進捗レコードあり
- 258件 / 72社: 目標と実績を接続済み
- 自動Deep Verification承認は禁止

旧評価値は履歴としてのみ保持し、現行品質の分母・分子には使用しない。

## 3. Phase 1

Phase 1は正式資料が明確な50社で新工程を検証する工程として開始し、50社すべての一次レビューを完了した。

新工程では最低限、以下を分離して記録する。

- 正式中期経営計画か、Growth資料・単年度予想・長期ビジョンか
- 実績か、予想か、中計終端目標か
- 年度、単位、連結・単体等の範囲
- 戦略テーマ
- 財務目標
- 資本政策・キャッシュアロケーション
- 株主還元方針
- 項目別の証跡
- 一次レビューと独立レビュー

## 4. Phase 2

Phase 2は追加450社を対象とし、Phase 1と合わせて一次レビュー500社へ到達する工程である。

2026-08-16の再突合後:

- Phase 2一次レビュー: **360 / 450社（80.0%）**
- Phase 1込み: **410 / 500社（82.0%）**
- 残り: **90社**
- 最新完了Wave: **Wave 38**
- 通常候補: **4社**
- 例外候補: **86社**

従来はPhase 2一次レビューを370社と集計していたが、会社コード単位で現行450社監査母集団、canonical一次レビュー成果物、過去Wave割当、completion overlayを再突合した結果、canonical成果物が存在する企業は360社だった。割当行や再マップ履歴を企業数として二重計上しないため、正本を360社へ補正した。

したがって、今後は単純に10社×9ウェーブを生成するのではなく、通常候補4社と例外86社を分離する。例外候補は資料同定、誤資料修復、source recovery等を先に完了させ、その後に一次レビュー成果物を作成する。

## 5. Wave 38で得た重要な品質示唆

Wave 38では10社の一次レビューを完了した。このウェーブでは、候補資料の自動解決結果に5社の資料取り違えを検出し、公式正本へ差し替えた。

## 6. 2026-08-16の完了台帳・キュー再突合

Wave 39の通常生成を試みたところ、既存generatorでは新規企業を0社しか選択できず失敗した。原因は、通常の`primary_review_candidate`を大半処理済みで、残件の大部分が例外キューへ移っていたためである。

再突合では以下を確認した。

- 現行Phase 2監査母集団: 450社
- canonical一次レビュー成果物: 360社
- 未レビュー: 90社
- 通常候補: 4社
- 例外候補: 86社
- 過去割当で成果物が欠けていた5社はcanonicalレビューを復旧済み
- 例外候補86社は `manual_source_relevance_check`、`pdf_identification_required`、`probable_wrong_document`、`source_recovery_required` に分かれる

今後のPhase 2は「次Waveを機械的に10社生成する」運用から、「通常候補を処理しつつ、例外キューのsource remediationを先に解消する」運用へ切り替える。

同時に、独立図表レビューも306社滞留している。

- Deep Verification最終承認: 0社

## 8. 公開同期

GitHubを企業データ・出典・品質判断の正本とし、公開サイトはその公開ビューとする。

現状はQuality Rebase後のGitHub正本と公開サイトの品質表示が完全同期していない。公開同期は以下を満たした状態で行う。

1. 公開対象データが現行品質定義を使用する
2. 旧5つ星表示を現行のDeep Verification件数と混同しない
3. 3,000社掲載件数と深掘り確認件数を分けて表示する
4. 企業詳細に正式中計 / Growth資料 / 単年度予想等の資料区分を表示する
5. 出典URL・確認日・レビュー状態を表示する
6. 公開後にリンク切れ・レンダリング・検索・フィルタを再検証する

## 9. 次のマイルストーン

### Milestone A — 通常候補4社の一次レビュー

現存する通常候補4社について、review inputと一次資料を確認し、canonical一次レビュー成果物を作成する。

### Milestone B — 例外86社のsource remediation

例外キューを4区分に分け、資料同定・誤資料修復・source recoveryを行う。正式中計が存在しない企業はその事実を明示し、別資料を無理に中計へ昇格させない。

### Milestone C — Phase 2 一次レビュー 450 / 450

Phase 1 50社 + Phase 2 450社 = 500社の一次レビューを、会社コード単位のcanonical成果物で完了する。

### Milestone D — 独立図表レビューの解消

古いWaveから独立図表確認を進め、年度・単位・図表の列見出し・実績/計画区分・資本政策の読み違いを再検証する。

### Milestone E — Deep Verification承認

一次レビューと独立レビューの双方を満たした企業から最終承認する。一次レビュアーによる自己承認は禁止する。

### Milestone F — 公開サイト同期

GitHub正本の品質状態を `chu-kei.com` へ反映し、公開後監査を完了する。

### Milestone G — 1,000社へ拡張

500社工程で得た誤資料率、差戻し理由、レビュー工数、独立確認のボトルネックを反映し、品質基準を維持したまま1,000社へ拡張する。

## 10. 品質ルール

- 会社公式PDFまたは会社公式IRページを一次資料として優先する
- 企業名・証券コード・資料名・公表日を確認する
- PDFは具体的ページ、Web資料は具体的見出し・URLを証跡として残す
- 正式中計、Growth資料、単年度予想、長期ビジョン、旧中計を分離する
- 実績、予想、中計終端目標を分離する
- 年度、単位、連結範囲を検査する
- 未開示値を推測で補完しない
- 比較不能なKPIに架空の進捗率を作らない
- 自動事実補完、自動承認、自動本番昇格を行わない
- 一次レビュアーは自分のレビューをDeep Verification承認しない
- 一次レビュー完了は会社コード単位のcanonicalレビュー成果物で数える
- 割当行数、再マップ行数、集計値だけでは完了扱いにしない
- 件数を増やすために品質基準を緩めない

## 11. 理想状態

> 日本企業の中期経営計画について、企業の発見、正式中計かどうかの判別、戦略比較、財務・資本政策比較、目標と実績の追跡、過去計画との差分、原文検証までを一つの場所で完結できる、信頼性の高い企業調査プラットフォーム。

## 12. 更新ルール

- 掲載企業数
- Phase 1 / Phase 2 一次レビュー件数
- 独立レビュー件数
- Deep Verification承認件数
- 進捗・実績接続件数
- 品質基準
- 公開同期状態
