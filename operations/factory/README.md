# ファクトリー運用基準（factory criteria v1）

Chu-kei Insight の定常運用（検知 → 正式登録 → 変更履歴 → SNS下書き → 計測）を「ファクトリー」として運用するための判定基準の正本。2026-11-23にオーナー指示（Notion フィールドガイド「A new shape for work」の実対応）を受けて作成した。

原則:

- 作業の前に「何をもって正しいとするか」をこの文書と各工程の正本で定義する。基準に無い判断が必要になったら、その場で基準側に追記してから作業する。
- 判断と検証結果は repo 内の記録に残す（下記「記録の正本」）。チャットの発言は記録の正本ではない。
- 数値の正本は一次資料と本番データであり、推測や二次情報で埋めない。確認できないものは「未確認」と記録する。
- 古くなった記述（context rot）を見つけたら、見つけた作業の中でその場で直す。数値の現況は本番インデックスと repo の機械ファイルを正とし、文書内の古い件数表記は現況として再掲しない。

## 1. 検知トリアージの基準

正本: `operations/detection/README.md`、記録先: `operations/detection/inbox-v1.json`

- 正式な計画とみなすのは、取締役会決議を伴う中期・中長期・長期の経営計画で、期間と定量的な最終年度目標を含むもの。決算説明資料のみ、事業計画及び成長可能性に関する事項のみ、Investor Day 資料のみは対象外とする。
- 判定は一次資料（TDnet 開示 PDF または企業公式資料）で行う。再検証レコードや要約の記述だけでは判定しない。
- 対象外と判定した場合は inbox の当該アイテムを dismissed とし、理由を事実ベースの note で残す。エントリは削除しない。
- 検知ジョブ自体はレジストリや公開データを変更しない。反映は一次レビューの PR フローでのみ行う。

## 2. 正式登録（一次レビュー）の基準

記録先: `operations/quality-rebase/phase2/primary-reviews/` のレビュー JSON、`operations/reviews/decisions.json`（訂正時）

- レビューは一次資料の全文確認を前提とし、次の検証項目をすべて満たすこと: 一次レビュー完了、企業同一性の確認、正式な計画であることの確認、全文レビュー完了、数値の検証、項目単位の根拠（ページ番号等）。
- 数値・タイトル・期間・日付はすべて一次資料と照合する。再検証レコードと一次資料が食い違う場合は一次資料を正とし、食い違いをレビュー内に記録する。
- 登録後は台帳（`operations/quality-rebase/phase2/effective-status-v1.json`）を実ファイル基準で再同期し、検証（quality:local:quick、証跡監査、フロントエンド予算）をすべて通過させる。
- マージ後は本番インデックスで登録状態を確認するまでを登録作業とする。
- 公開データの訂正には、対応するレビュー判断記録（`operations/reviews/decisions.json`）を必ず紐付ける。

## 3. 変更履歴の記録基準

正本: `operations/history/PLAN-EVENTS.md`、記録先: `operations/history/plan-events-v1.json`

- イベントは追記のみとし、削除・改変しない。
- 各イベントには dateBasis（verified = 再検証で確認した日付、disclosed = 開示日）を必ず付け、両者を混ぜない。
- 検知経由のイベントには detectionId を付け、recordedVia を保持する。

## 4. SNS 下書きの基準

正本: 投稿方針 v1（オーナー承認済み、運用ファイルとして保持）、記録先: 専用チャットでの承認履歴と日次ログ

- 投稿は事実のみ。数値は一次資料で検証済みのものだけを使う。投資助言・株価への言及・推奨表現・計画の良し悪しの評価は入れない。
- 下書きには推奨する投稿タイミングを必ず添える。承認が推奨時間帯を過ぎた場合は、投稿可否を再判断してから出す。
- トレンド便乗は「強い一致」（登録済み企業のトレンド入り、またはサイトのテーマへの直接対応）のみ。不祥事・情報漏洩・事故・災害などのネガティブな話題、株価の動きそのもの、事業と無関係な話題は対象外とする。
- 実投稿はオーナーの承認後。Threads / Instagram は承認カード経由、X はオーナーがアプリで投稿する。

## 5. 計測の合否基準

正本: `operations/measurement/README.md` の「合否基準」節。週次・月次の報告には各指標の合否を明記する。合否の判定に使えない数値は「未確認」とし、合否を推測で付けない。

## 6. 記録の正本

- 訂正とレビュー判断: `operations/reviews/decisions.json`
- 検知の処理状態: `operations/detection/inbox-v1.json`
- 計画の変更履歴: `operations/history/plan-events-v1.json`
- 一次レビューの内容: `operations/quality-rebase/phase2/primary-reviews/`
- 計測結果: `operations/measurement/log-v1.md`（追記のみ、過去行は書き換えない）
- 運用基準: 本書および各工程の README / 方針文書
